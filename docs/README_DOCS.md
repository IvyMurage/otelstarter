# OTelStarter documentation

Start here when working on the repository.

For an overview of the whole project, every file included, read the [project guide](PROJECT_GUIDE.md) first.

Then, before changing how the project is built:

1. [Architecture](ARCHITECTURE.md): the system design and its boundaries.
2. [Requirements](REQUIREMENTS.md): what the product must do.
3. [Engineering guidelines](ENGINEERING_GUIDELINES.md): the rules every change follows.
4. [Domain events](DOMAIN_EVENTS.md): the business-event contract.

Contributing: start with [CONTRIBUTING.md](../CONTRIBUTING.md). To support another library or language, see [adding a library or a language](adding-a-language.md).

Using otelstarter: the [quickstart](quickstart.md), and one page per command: [analyze](analyze.md), [init](init.md), [run](run.md), [validate](validate.md). The [telemetry conventions](TELEMETRY_CONVENTIONS.md) and [performance](performance.md) pages cover what the SDKs send and what they cost. Decisions and their reasons are in [docs/adr](adr/).
